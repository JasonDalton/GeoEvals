# Datasets

Every data asset a benchmark uses is described by a dataset manifest: one per benchmark
(`benchmarks/<name>/manifest.yaml`) and one per dataset that may not be committed
(`datasets/manifests/<dataset_id>.yaml`, with download steps in `download_instructions/`).
A manifest records each asset's source, license, attribution, checksum, CRS, extent, time
range, processing steps and known limitations; the schema is
[`schemas/dataset-manifest.schema.json`](../schemas/dataset-manifest.schema.json). Data rules
are in [`docs/data-governance.md`](../docs/data-governance.md).

## License inventory

One row per asset in every manifest under `benchmarks/` and `datasets/manifests/`.
"Redistributable" says whether the license lets the asset be committed to this repository;
assets marked **no** live only in the gitignored `data/raw/` and are fetched with
`geoevals data fetch <dataset_id>`. "Used by" names the benchmark (or pilot build) that reads
the manifest.

The table is generated: run `uv run geoevals data inventory` after editing a manifest. CI runs
`geoevals data inventory --check` and fails if the committed table is out of date.

## Benchmark dataset cards

Each benchmark directory has a dataset card, `benchmarks/<name>/README.md`, with the sections
Purpose, Collection process, Geography, Time range, Schema, License, Limitations, Intended
uses and Prohibited uses. `tests/test_dataset_cards.py` fails if a card or one of these
sections is missing.
